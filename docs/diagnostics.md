# Preview diagnostics

Settings → **Diagnostics and local storage** reads cached runtime/native readiness and known saved preference choices, plus metadata for the owned profile's three fixed database, WAL and SHM files. It does not query SQLite, enumerate history, call SNU, or probe Windows notifications. The measurement is a local sample, not one coherent database/source snapshot. A missing sidecar is ordinary; unavailable metadata is never reported as zero.

The optional JSON export has an explicit versioned whitelist and a 64 KiB limit. It contains numeric assembly/runtime versions, closed status/preference enums, booleans, the local capture time and byte lengths only. It omits database contents, course/watch/event identities, labels, academic selections, paths, URLs, cookies, exception messages and arbitrary diagnostic codes. Export is a manual local action and uploads nothing. Review the report before sharing it; it still describes app configuration and local storage use.

Choose a **new filename** in the Save dialog. Existing files are never replaced. Canceling the dialog creates no file. If shutdown/cancellation arrives while the modal dialog is open, the app retains that actual operation until the dialog is dismissed. Once a bounded create-new write starts, it finishes and flushes without interruption; a completed save remains a completed save after late cancellation. A failed disk write can leave an incomplete file at the selected destination, and the UI reports failure without claiming success. No raw database or watch-list backup is produced.

The **256 MiB** warning is an application policy for this preview, measured over the database and present sidecars. It does not delete data, prune history, stop actors or impose a hard storage limit. Semantic retention must preserve delivery, recipient and recovery authority and remains deferred. Automatic updates, automatic startup and a watch backup/restore workflow also remain deferred; diagnostics is not a substitute for any of them.

Implementation boundaries: Application owns immutable bounded diagnostic contracts; Windows owns projection, metadata and explicit JSON/file writing; Desktop owns the destination dialog; Settings owns/drains commands independently of preference saves and native tests. Export fields must be added deliberately to the serializer rather than serializing arbitrary runtime objects.
